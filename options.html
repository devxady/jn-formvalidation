Constructor options

Pass an options object to new JnFormValidation(options). The constructor automatically calls jnSetupValidation().

OptionTypeDefaultDescription
formClassString""CSS selector passed to document.querySelectorAll. An empty value logs a message and skips setup.
showErrorMessagesBooleantrueWhen true, append a field error message. When false, add a red inline outline to invalid controls.
errorMessagesObjectBuilt-in mapOverrides matching default message keys. Unspecified keys keep their built-in messages.

The option names are case-sensitive. Use a selector string, including its punctuation, such as ".jnForm".

JavaScript
const validation = new JnFormValidation({
  formClass: ".profile-form",
  showErrorMessages: true,
  errorMessages: {
    email: "Enter a work email address.",
    text: "This field cannot be empty."
  }
});

What each type checks

These checks are intentionally documented as implemented. They are basic client-side checks, not complete domain validation.

  • Email uses a basic address pattern; it is not a full email-address standards check.
  • Telephone requires exactly ten digits. Number accepts digits only (integer values).
  • URL requires an ftp://, http://, or https:// prefix.
  • Password and text check only whether the trimmed value is empty; no password-strength rule is implemented.
  • File accepts PNG, JPEG, GIF, or PDF MIME types. It does not inspect file size.
  • Date, time, datetime-local, month, week, range, and color check for an empty value; no range or date-bound configuration is implemented.
  • Checkbox and radio checks query controls with the same name inside the form. Provide a shared, non-empty name for each group.

Implemented API

APIKindBehavior
new JnFormValidation(options)ConstructorMerges options with defaults and automatically sets up submit validation for matching forms.
jnSetupValidation()Instance methodSets up validation. Called by the constructor; calling it again can attach another submit listener.

No callbacks, events, promise API, or live-as-you-type methods are implemented in the current source.

Known behavior in 2.0.0

Outline mode limitation: when showErrorMessages is false, the library sets an inline outline. Its reset code removes a CSS class rather than that inline style, so the outline can remain after a later submit. This website documents the current behavior and does not change the library.

Validation messages are not automatically linked to fields by the library. The site’s own demo adds alert roles and field associations as a website-only accessibility enhancement; those attributes are not part of the library API.
