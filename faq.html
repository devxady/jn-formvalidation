Common questions

Does validation run while someone types?

No. The current library adds a submit listener. Previous messages clear and reappear on the next submit attempt.

Why is my field not checked?

Make sure the form matches the formClass CSS selector and that the field is inside a .jn-input-wrap. The validator checks only the first input, select, or textarea inside each wrapper.

Do I need the HTML required attribute?

No. The library checks the supported field types itself. Add novalidate to the form if browser constraint validation would otherwise stop the submit event before the library runs.

What happens after a valid submission?

The current implementation calls the form’s native submit() method. Set the intended action and method; the call bypasses other submit listeners and browser constraint validation.

Can I customize just one message?

Yes. Pass an errorMessages object with the matching key. For example, { email: "Use a valid address." } changes the email message while other defaults remain.

Is there an npm package or a framework adapter?

This repository provides browser-ready JavaScript and CSS files and a downloadable ZIP. It does not include an npm manifest or framework adapter.

Does the library replace server validation?

No. Client-side validation helps people correct input; always validate submitted data again on the server.

Which browsers are supported?

The source uses modern JavaScript syntax. The older compatibility list from the previous documentation is not backed by a current test matrix, so this site does not claim support for legacy browsers.

Need more help?

Share the version, the form markup, and the exact steps to reproduce a problem. Use the support page or open an issue in the project repository.
