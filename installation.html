Documentation · Installation

Install the files you need.

The repository provides a version 2.0.0 ZIP and browser-ready JavaScript and CSS files. There is no verified npm package in this project, so this guide covers the supported file-based setup.

1. Choose how to include the files

Download the package

Download JN Form Validation 2.0.0 and extract the ZIP. Its root contains assets/css/, assets/js/, index.html, and README.md.

Copy the package’s assets directory into your project, or reference the files in the extracted directory. Use these paths when your HTML sits beside the assets directory:

HTML
<link rel="stylesheet" href="assets/css/jn-formvalidation.min.css">
<script src="assets/js/jn.formvalidation.min.js"></script>

Use the repository CDN files

The project’s existing installation guide references jsDelivr files from the repository’s current default branch. These URLs follow that branch rather than pinning an immutable release tag.

HTML
<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/chauhan07/jn-formvalidation/code/assets/css/jn-formvalidation.min.css">
<script
  src="https://cdn.jsdelivr.net/gh/chauhan07/jn-formvalidation/code/assets/js/jn.formvalidation.min.js"></script>
Version note: the ZIP in this repository is named jn-form-validation-2.0.0.zip. The CDN URLs above preserve the paths already used by the project; use the ZIP when you need a locally stored copy of that named package.

2. Prepare the form

Use a CSS selector for the form class you plan to pass to formClass. Place each field to check inside its own .jn-input-wrap. Add a visible label and a unique control ID. The library checks recognized fields on submit without requiring HTML required attributes.

HTML
<form class="account-form" action="/account" method="post" novalidate>
  <div class="jn-input-wrap">
    <label for="account-email">Email</label>
    <input id="account-email" name="email" type="email">
  </div>
  <button type="submit">Save</button>
</form>

novalidate lets the library’s submit handler inspect empty or malformed values instead of having native browser validation stop the submit event first. Choose your actual form action and method; server-side validation is still required.

3. Initialize validation

After the library script and the form markup are loaded, create one instance. formClass accepts a CSS selector, so use the leading dot for a class name.

JavaScript
const accountValidation = new JnFormValidation({
  formClass: ".account-form",
  showErrorMessages: true
});

When the form is submitted, invalid values get the default message for their input type. The options reference explains how to change the selector, message mode, and individual messages.

4. Try the setup

Submit with the email field empty or with an invalid address. The library should prevent that attempt and add a message inside the field wrapper. Enter a valid address and the form will continue to the configured action.

Production reminder: the library calls form.submit() after its checks pass. That submits to the form’s configured destination and bypasses other submit listeners. Do not point a production form at an unintended destination.

For a no-endpoint interactive preview, use the examples page; its valid form submits to a blank local frame.
