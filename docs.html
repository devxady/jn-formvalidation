Understand the setup.

JN Form Validation is a small JavaScript library that checks selected form fields when a form is submitted, then adds field-level error feedback when a check fails.

Overview

The library attaches a submit listener to every form matched by formClass. When a visitor submits, it checks the first input, select, or textarea inside each .jn-input-wrap. If a check fails, it prevents that submission and adds a message by default. If every checked field passes, it calls the form’s native submit() method.

It is a client-side usability aid. Validate submitted data again on your server; browser code cannot be a security boundary.

Important: the current 2.0.0 implementation checks every recognized wrapped field, whether or not it has an HTML required attribute. Use novalidate when you want this library to receive empty or malformed values before the browser blocks submission.

Quick start

  1. Include the library JavaScript and its optional error styles.
  2. Add a selector class to the form and jn-input-wrap to each field wrapper.
  3. Initialize JnFormValidation once after the form markup.
HTML
<link rel="stylesheet" href="assets/css/jn-formvalidation.min.css">

<form class="signup-form" action="/signup" method="post" novalidate>
  <div class="jn-input-wrap">
    <label for="signup-email">Email</label>
    <input id="signup-email" name="email" type="email">
  </div>
  <button type="submit">Create account</button>
</form>

<script src="assets/js/jn.formvalidation.min.js"></script>
<script>
  new JnFormValidation({
    formClass: ".signup-form",
    showErrorMessages: true
  });
</script>

Set action and method to the endpoint your application uses. The example endpoint above is illustrative; it is not provided by this library.

Form and field structure

formClass is passed to document.querySelectorAll, so provide a CSS selector such as ".signup-form" or "form.needs-validation". Every field to check must be inside an element with the class jn-input-wrap. The wrapper can be a div or a label; use explicit labels and matching IDs for accessible names.

The library reads one control from each wrapper. Keep one field control in a wrapper. For a checkbox or radio group, place the group in one wrapper and give all group members the same non-empty name.

HTML
<div class="jn-input-wrap">
  <label for="account-name">Account name</label>
  <input id="account-name" name="accountName" type="text">
</div>

How validation runs

  1. A matching form receives a submit listener during construction.
  2. On submit, previous message elements and wrapper error classes are cleared.
  3. Each .jn-input-wrap is checked using its first input, select, or textarea.
  4. Invalid values receive the configured message (or an outline when messages are disabled).
  5. If all checked fields pass, the library submits the form using form.submit().
Submission behavior: the native form.submit() call bypasses other submit listeners and browser constraint validation. Give production forms a real action and server-side validation. Use the demo page to try the library without an application endpoint.

Error messages

With showErrorMessages: true, an invalid wrapper receives .jn-error-wrap and a child .jn-error-message. The distributed stylesheet provides basic red error styling; the site demo adds an accessible alert role to these generated messages.

Messages are cleared on the next submit attempt, not as the user types. Override only the message keys you need with the errorMessages option. See the default message reference.

Compatibility and scope

The published package contains plain JavaScript and CSS files and has no runtime package-manager dependency. The source uses modern JavaScript syntax, including classes and object spread. The old browser/device list in the previous guide was not backed by a current test matrix, so no legacy-browser support is claimed here.

See the supported input reference for the actual checks and their limits. This release does not provide live-on-input validation, async rules, or a callback API.
